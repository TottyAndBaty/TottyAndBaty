gin的post只能读一次的问题

2026年8月5日 · 2 分钟 · 223 字 · beyond

最近使用gin时，使用webhook方式接受对方数据，发现在中间件里面验证数据格式后，在后续代码里面，读取post居然为空

以下是演示代码

func main() {

	server := gin.New()
	server.Use(middlewares.RequestLogger)

	server.POST("/posts", func(c *gin.Context) {
		err := postController.Save(c)
		if err != nil {
			c.JSON(http.StatusBadRequest, gin.H{
				"error": err.Error(),
			})
		} else {
			c.JSON(http.StatusOK, gin.H{
				"message": "Input is Valid!",
			})
		}
	})

	server.Run(":8080")
}

中间件读取代码

func RequestLogger(c *gin.Context) {
	tmp := tmp(c.Request.Body)
	b, _ := ioutil.ReadAll(tmp) // read the request to b
	c.Next()
	fmt.Printf("Request: %s\n", string(b))

}

func tmp(body io.ReadCloser) io.ReadCloser {
	return body
}

因为 c.Request.Body 的类型是 io.ReadCloser，它本质上是一个流（stream），数据只能按顺序读取一次。第一次读取完成后，内部的读取指针已经移到了末尾，再次读取就会返回空数据或 EOF 错误。

常见触发场景#

  • 在中间件里调用了 c.GetRawData() 或 io.ReadAll(c.Request.Body)，然后在 handler 里再调用 c.ShouldBindJSON()，第二次就会报错 EOF
  • 多次调用 c.ShouldBind() 或 c.ShouldBindJSON()
  • 日志中间件打印了请求体，导致后续业务代码读不到数据

解决方案#

方案一：读取后手动重置 Body（最常用）#

读取完 Body 后，用 io.NopCloser + bytes.NewBuffer 把数据写回去：

func MyMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        bodyBytes, _ := io.ReadAll(c.Request.Body)
        
        // 打印日志等操作...
        fmt.Println("body:", string(bodyBytes))
        
        // 关键：把数据写回 Body，让后续代码能再次读取
        c.Request.Body = io.NopCloser(bytes.NewBuffer(bodyBytes))
        
        c.Next()
    }
}

注意：ioutil.NopCloser 和 ioutil.ReadAll 在 Go 1.16+ 已被废弃，推荐使用 io.NopCloser 和 io.ReadAll。

方案二：使用 ShouldBindBodyWith（Gin 1.4+）#

如果你需要在多个地方绑定同一个请求体到不同的结构体，用这个方法：

// 第一次绑定
c.ShouldBindBodyWith(&req1, binding.JSON)

// 第二次绑定，不会报 EOF
c.ShouldBindBodyWith(&req2, binding.JSON)

它的原理是将 Body 缓存到 Gin 的上下文中，后续绑定直接从缓存读取。

方案三：全局中间件统一处理#

如果你经常需要多次读取 Body，可以注册一个全局中间件：

r := gin.Default()

r.Use(func(c *gin.Context) {
    all, err := c.GetRawData()
    if err != nil {
        log.Fatal(err)
    }
    // 重写 GetBody 方法，支持重复读取
    c.Request.GetBody = func() (io.ReadCloser, error) {
        return io.NopCloser(bytes.NewBuffer(all)), nil
    }
    // 重置 Body
    body, _ := c.Request.GetBody()
    c.Request.Body = body
    c.Next()
})

这个中间件必须注册在最前面，确保在其他中间件和 handler 之前执行。

📌 总结#

方案 适用场景 注意事项
手动重置 Body 中间件中读取后需要后续继续用 每次读取后都要写回
ShouldBindBodyWith 同一请求绑定多个结构体 Gin 1.4+ 才支持
全局中间件 全局需要多次读取 Body 必须注册在最前面

核心原因就一句话：io.ReadCloser 是一次性流，读完就没了，需要手动"回填"才能再读。
